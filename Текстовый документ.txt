# PRD — Автоматизированная система учёта основных средств (АС Учёт ОС)

**Версия:** 1.0  
**Дата:** 25 июня 2026 г.  
**Статус:** Draft  
**Автор:** Технический отдел

---

## 1. Обзор продукта

### 1.1 Назначение

АС Учёт ОС — внутренняя веб-система для технических специалистов компании, обеспечивающая совместный учёт основных средств (ОС) по инвентарным и серийным номерам, контроль их технического состояния, местонахождения и жизненного цикла.

### 1.2 Проблема

До внедрения системы учёт ОС ведётся разрозненно: в таблицах Excel, на бумаге или в устных договорённостях. Это приводит к:

- отсутствию актуальных данных о местонахождении ОС;
- невозможности быстро определить, за кем закреплено конкретное оборудование;
- несвоевременному выявлению ОС, требующих замены или модернизации;
- отсутствию истории перемещений и обслуживания.

### 1.3 Цель

Создать единую систему, в которой в любой момент можно получить ответ на вопросы:

- Где находится любое ОС?
- За кем оно закреплено?
- В каком оно состоянии?
- Какие действия с ним производились?

| Роль | Сценарий использования |
|---|---|
| Технический специалист / ИТ-инженер | Регистрация ОС, перемещение, обслуживание |
| Системный администратор | Управление серверным и сетевым оборудованием |
| Руководитель технического отдела | Просмотр сводных отчётов, контроль состояния парка |
| Бухгалтер / материально-ответственное лицо | Сверка данных по инвентарным номерам |

## 3. Функциональные требования

### 3.1 Реестр основных средств

- Регистрация ОС с обязательными полями: инвентарный номер, серийный номер, наименование, дата постановки на учёт.
- Поиск по инвентарному номеру, серийному номеру, наименованию, ответственному лицу.
- Фильтрация по состоянию ОС и местонахождению.
- Просмотр карточки ОС с полной информацией и историей.
- Экспорт реестра (в форматах Excel / CSV).

### 3.2 Учёт технического состояния

Каждое ОС имеет одно из четырёх состояний:

| Состояние | Описание |
|---|---|
| Рабочее | Эксплуатируется в штатном режиме |
| Не рабочее | Вышло из строя, не эксплуатируется |
| Требует замены | Физический или моральный износ, ремонт нецелесообразен |
| Требует модернизации | Расширение, обновление компонентов или ПО |

- Смена состояния фиксируется с указанием причины, даты и ответственного.
- История изменений состояния сохраняется в карточке ОС.

### 3.3 Закрепление за сотрудниками

- Привязка ОС к конкретному сотруднику (ответственному лицу).
- Учёт сотрудника по: ФИО, должности, подразделению, корпоративной учётной записи (e-mail).
- Просмотр всех ОС, закреплённых за конкретным сотрудником.
- Передача ОС от одного сотрудника другому с фиксацией в истории.

### 3.4 Учёт местонахождения

- Закрепление ОС за подразделением / локацией.
- Просмотр распределения ОС по подразделениям с количественными показателями.
- Поддерживаемые локации: ИТ-отдел, Бухгалтерия, Серверная, Отдел кадров, Руководство, Склад (расширяемый справочник).

### 3.5 Перемещения

- Оформление акта перемещения ОС: откуда, куда, ответственный, дата, причина.
- Статусы перемещения: ожидает, в процессе, завершено.
- Полная история перемещений в карточке ОС.
- Журнал всех перемещений с фильтрацией.

### 3.6 Обслуживание и модернизация

- Создание заявок на ТО, ремонт или модернизацию с указанием типа работ, исполнителя, даты и описания.
- Типы работ: плановое ТО, диагностика, ремонт, замена компонентов, обновление ПО/прошивки.
- Статусы заявок: в работе, выполнено, отменено.
- История обслуживания в карточке ОС.

### 3.7 Утилизация и списание

- Оформление акта списания с указанием причины, даты и подтверждения.
- Причины списания: физический износ, моральный износ, выход из строя, утрата.
- Статусы: на утилизации, списан.
- Списанные ОС сохраняются в архиве реестра.

### 3.8 Панель мониторинга

- Сводные метрики: общее количество ОС, из них рабочих, требующих действий, в перемещении.
- Диаграмма распределения по состояниям.
- Лента последних событий (добавление, перемещение, смена состояния, ТО, списание).

### 3.9 Отчётность

- Сводный отчёт по всем ОС (инвентарный номер, наименование, ответственный, местонахождение, состояние).
- Отчёт по ОС, требующим замены или модернизации, с рекомендуемыми действиями.
- Отчёт по перемещениям за период.
- Отчёт по обслуживанию за период.

## 5. Структура данных (ключевые сущности)

### Основное средство (Asset)
```
- id                  — уникальный идентификатор
- inv_number          — инвентарный номер (уникальный)
- serial_number       — серийный номер
- name                — наименование
- location_id         — местонахождение (FK → Location)
- employee_id         — ответственный сотрудник (FK → Employee)
- status              — состояние: working | broken | replace | upgrade
- added_date          — дата постановки на учёт
- notes               — примечания
```

### Сотрудник (Employee)
```
- id
- full_name           — ФИО
- email               — корпоративная учётная запись
- position            — должность
- department_id       — подразделение (FK → Location)
```

### Местонахождение (Location)
```
- id
- name                — название подразделения / локации
```

### Перемещение (Movement)
```
- id
- asset_id            — FK → Asset
- from_location_id    — откуда
- to_location_id      — куда
- employee_id         — ответственный
- date                — дата
- reason              — причина
- status              — in_progress | completed | pending
```

### Обслуживание (Maintenance)
```
- id
- asset_id            — FK → Asset
- type                — тип работ
- description         — описание
- executor_id         — исполнитель (FK → Employee)
- date                — дата
- result_status       — выполнено | в работе | отменено
```

### Списание (Disposal)
```
- id
- asset_id            — FK → Asset
- reason              — причина
- date                — дата
- approved_by         — кем утверждено
- status              — на утилизации | списан
```

## 6. Пользовательские сценарии (User Stories)

### 6.1 Регистрация нового ОС
**Как** технический специалист,  
**я хочу** добавить новое ОС в реестр,  
**чтобы** оно было учтено с первого дня эксплуатации.

Критерии приёмки:
- Поля инвентарный номер и наименование — обязательные.
- Система проверяет уникальность инвентарного номера.
- После сохранения ОС появляется в реестре и на панели мониторинга.

### 6.2 Поиск местонахождения ОС
**Как** технический специалист,  
**я хочу** найти любое ОС по инвентарному или серийному номеру,  
**чтобы** моментально узнать, где оно находится и за кем закреплено.

Критерии приёмки:
- Поиск работает по частичному совпадению.
- Результат показывает местонахождение, ответственного и текущее состояние.

### 6.3 Изменение состояния ОС
**Как** технический специалист,  
**я хочу** изменить состояние ОС после диагностики,  
**чтобы** коллеги видели актуальный статус оборудования.

Критерии приёмки:
- Изменение состояния требует указания причины.
- Предыдущее состояние сохраняется в истории с датой и автором.

### 6.4 Оформление перемещения
**Как** технический специалист,  
**я хочу** оформить перемещение ОС в другое подразделение,  
**чтобы** данные о местонахождении всегда были актуальны.

Критерии приёмки:
- Акт перемещения фиксирует: ОС, откуда, куда, дату, ответственного.
- После подтверждения местонахождение ОС обновляется автоматически.

### 6.5 Формирование отчёта по проблемным ОС
**Как** руководитель технического отдела,  
**я хочу** получить список ОС, требующих замены или модернизации,  
**чтобы** спланировать бюджет на закупку и ремонт.

Критерии приёмки:
- Отчёт включает инвентарный номер, наименование, ответственного, рекомендацию.
- Отчёт экспортируется в Excel.

## 7. Навигация и модули системы

```
АС Учёт ОС
├── Панель мониторинга      — сводные метрики и лента событий
├── Реестр ОС               — полный список с поиском и фильтрами
├── Местонахождение         — распределение по подразделениям
├── Ответственные лица      — сотрудники и их ОС
├── Перемещения             — журнал актуальных и завершённых перемещений
├── Обслуживание            — заявки на ТО и модернизацию
├── Утилизация              — акты списания
└── Отчёты
    ├── Сводный отчёт по всем ОС
    └── ОС, требующие внимания
```

## 10. Ограничения и допущения

- Система предназначена для использования во внутренней сети компании.
- Первичная загрузка данных (импорт существующего реестра) выполняется через CSV-импорт.
- Интеграция с бухгалтерской системой (1С и др.) — вне рамок текущей версии, планируется в v2.0.
- Мобильная версия — вне рамок v1.0.
